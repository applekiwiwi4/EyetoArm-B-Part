# EyetoArm · B파트 (카메라 보정 · 좌표 변환)

> 카메라로 컨베이어 위 볼트를 인식하고, 로봇팔(UR5e)이 규격별 상자에 분류하는 **4인 팀 프로젝트**에서
> **카메라 픽셀을 로봇 좌표(mm)로 바꾸고 볼트 규격을 판정하는 B파트**를 맡았습니다.

- 팀 저장소 (전체 코드): https://github.com/didgustmd23/EyetoArm
- 기간: 2026.11 · 5주 (KH 아카데미 팀 프로젝트)
- 환경: ROS 2 Jazzy · Gazebo · UR5e · Python · OpenCV · NumPy

---

## 1. 내가 맡은 일

A(인식)가 영상에서 찾은 **볼트 양 끝점 픽셀**을 받아서, C(로봇)가 바로 집을 수 있는 **집기 명령**으로 바꿉니다.

```
볼트 끝점 픽셀 2개
   │  ① 카메라 보정값 + 촬영 순간 카메라 위치 → 픽셀마다 광선
   │  ② 광선이 볼트가 놓인 높이와 만나는 점 = 실제 위치(mm)
   │  ③ 두 점 사이 길이로 규격 판정 (14~27mm 작은 볼트 / 36~52mm 큰 볼트)
   ▼  ④ 볼트 가운데 집는 점 · 그리퍼 닫는 방향 · 넣을 상자
C에게 집기 명령 전송 (/sort_part)
```

**픽셀을 좌표로 바꾸는 원리**
카메라 렌즈 특성으로 픽셀이 카메라에서 어느 방향인지 알아내고, 그 방향으로 직선(광선)을 긋습니다. 볼트는 벨트 위 정해진 높이에 누워 있으므로, 이 직선이 그 높이와 만나는 점이 볼트의 실제 위치가 됩니다.

## 2. 다른 파트와의 연동

```
[A 인식] ──끝점 픽셀──▶ [B 좌표 변환] ──집기 명령──▶ [C 로봇 실행]
 YOLO 분할                (담당)        ◀──결과───      UR5e · 그리퍼
                            │
                            └──중심점 영상──▶ [D 대시보드]
```

| 연결 | 주고받는 값 | 방식 |
|---|---|---|
| A → B | 볼트 양 끝점 픽셀, 추적 번호, 촬영 시각 | 같은 프로그램 안 함수 호출 |
| B → C | 집는 위치(mm), 닫는 방향, 규격, 상자 위치 | ROS 2 액션 `/sort_part` |
| C → B | 성공 / 실패 이유 | 액션 결과 |
| B → D | 판정·중심점을 그린 영상 | ROS 토픽 `/b/center_overlay/image` |

파트 사이에 주고받는 값은 **협업 요청서**에 적고, 상대 파트의 회신을 받아 맞췄습니다.

## 3. 결과

| 항목 | 결과 |
|---|---|
| 볼트 중심 위치 오차 (멈춘 벨트) | **1.5mm 이내** |
| 벨트 방향 위치 오차 (움직이는 벨트) | **약 1mm** |
| B 좌표로 잰 벨트 속도 | 19.4~20.5 mm/s (실제 20 mm/s) |
| 볼트 방향(각도) 오차 | 1~5° |
| 규격 판정 | 작은 볼트·큰 볼트 모두 정답 |

정답 기준: Gazebo 시뮬레이터가 알고 있는 실제 볼트 위치와 모델 치수

## 4. 해결한 문제 (주요 3가지)

**① 높이 보정이 두 파트에 중복** · [PR #167](https://github.com/didgustmd23/EyetoArm/pull/167)
작은 볼트를 2mm 낮게 잡는 보정이 B와 C 양쪽에 들어가 있었습니다. 실행 경로에 따라 4mm가 내려가서, 손끝이 벨트 아래로 파고들며 실패했습니다.
→ B에서 빼고 C 한 곳에만 두어 해결했습니다.

**② 비스듬한 볼트를 버리는 문제** · [PR #172](https://github.com/didgustmd23/EyetoArm/pull/172)
볼트를 각도별로 돌려 놓고 시험하는 스크립트를 만들었습니다. 비스듬할수록 길이가 짧게 잡혀 판정 범위 밖으로 빠지는 것을 찾았습니다.
→ 작은 볼트 길이 하한을 17mm에서 14mm로 조정했습니다.

**③ 그리퍼 떨림 원인 추적**
처음에는 설정 문제로 단정했다가, 조건을 하나씩 바꿔 비교한 뒤에야 물리 엔진(Bullet)이 원인인 것을 확인했습니다.
→ DART로 바꿔 해결했고, "단정하기 전에 비교 시험부터"를 배웠습니다.

전체 기록: [docs/troubleshooting.md](docs/troubleshooting.md)

## 5. 남은 과제

- B 계산 시간 제한(20ms)을 넘으면 명령이 버려지는 문제 → A 파트와 기준을 합의해 조정 예정
- 중심점 영상 처리가 A 처리 속도를 늦춘다는 피드백 → 그리는 작업을 별도 스레드로 분리 예정
