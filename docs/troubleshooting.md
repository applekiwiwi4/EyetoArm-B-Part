# EyetoArm B파트(보정·좌표) 문제 해결 기록

> KH 아카데미 4인 팀 프로젝트 **EyetoArm** — 카메라로 컨베이어 위 볼트·너트를 인식하고, Gazebo 속 UR5e 로봇이 규격별 상자에 넣는 시스템.
> 나는 **B파트(보정·좌표)**를 맡았다. A(인식)가 준 볼트 끝점 픽셀을 로봇이 쓰는 mm 좌표로 바꾸고, 규격을 판정해 C(로봇 서버)에 집기 목표(`/sort_part`)를 보낸다.
>
> 기간: 2026-11-22 ~ 11-24 (통합 시험) · 팀 저장소: `didgustmd23/EyetoArm`

---

## 1. B파트가 하는 일

```
A 끝점 픽셀 2개 ──▶ ① 카메라 광선 (K·TF) ──▶ ② 높이 평면과 교점 = mm
                  ──▶ ③ 길이로 규격 판정 (BOLT_A / BOLT_B)
                  ──▶ ④ 집는 점·닫는 방향·상자 위치 ──▶ C /sort_part
```

- 카메라 보정값(K)과 촬영 순간 카메라 위치(TF)로 픽셀마다 광선을 만든다.
- 볼트가 누운 높이 평면(작은 볼트 102.7 mm, 큰 볼트 105 mm)과 광선이 만나는 점이 작업대 mm 좌표다.
- 두 끝점 거리로 규격을 정하고, 축 가운데를 집는 점으로 잡아 C에 보낸다.

## 2. 해결한 문제

### 2.1 그리퍼가 볼트를 물고 떨다가 시간 초과 (11-22)
- **현상:** 로봇이 볼트까지 내려가 잡는 데까지 가는데, 그리퍼가 떨리다 시간 초과로 원위치.
- **처음 판단(틀림):** "그리퍼 설정 문제", "데모 파일 변경 때문"이라고 단정했다가, 팀원 지적 후 다시 시험.
- **확인:** 예전 데모 파일도 물리 엔진 **Bullet**에서는 실패, **DART**에서는 성공.
- **해결:** C가 기본 물리 엔진을 DART로 변경. B 시험 서버 시작 로그에 DART 권장 안내 추가.
- **배운 점:** 원인을 단정하기 전에 조건 하나씩 바꿔 비교 시험부터 할 것.

### 2.2 작은 볼트(M3) 헛잡음 (11-22)
- **원인:** 손끝 길이 0.0543 m로 계산하면 손끝이 지름 3 mm 축의 한가운데에서 멈춤.
- **해결:** `FINGER_REACH` 0.0543 → **0.0533 m**. 두 볼트 모두 상자까지 성공.

### 2.3 A가 시작하자마자 KeyError (11-22)
- **원인:** B 규격 파일(`part_specs.json`) 수정 중 `length_tolerance` 키가 빠져 A의 추적 코드가 실패.
- **해결:** 키 복구. 남이 읽는 설정 파일은 키를 지우기 전에 누가 쓰는지 검색할 것.

### 2.4 B 좌표가 움직이는 벨트에서도 맞는지 검증 (11-23)
- 벨트 0.02 m/s에서 B 중심점으로 볼트 속도를 계산 → **19.4~20.5 mm/s** (실제 20 mm/s).
- 출발·도착 위치를 Gazebo 정답과 비교 → 벨트 방향 오차 **약 1 mm**.

### 2.5 볼트 머리를 육각으로 교체 → 규격 값 반영 (B-14, 11-23, PR #158)
- A가 둥근 머리 볼트가 벨트에서 굴러떨어져 ISO 4017 육각 볼트로 교체 → B 규격 갱신 요청.
- 전체 길이(22/44 mm), 머리 높이(2/4 mm), 기준 높이 102.7 mm, 큰 볼트 길이 하한 36 mm, 정확도 도구 정답 위치 계산을 육각 기준으로 변경.
- 멈춘 벨트에서 두 볼트 모두 판정 정답, 중심 오차 **≤1.5 mm**.

### 2.6 작은 볼트 집는 높이 −2 mm 중복 (11-23~24, PR #167)
- **11-23:** 벨트 멈춤 상태에서 C 서버가 작은 볼트를 축 가운데 높이로 잡아 미끄러짐(MISSED). C 데모는 작은 볼트만 2 mm 낮게 잡아 성공 → B 목표 높이에 −2 mm 추가 → **두 볼트 모두 상자 성공**.
- **11-24:** C 자동 분류(벨트 이동) 경로는 C 코드가 이미 −2 mm를 더하고 있어 **B와 합쳐 −4 mm** → 손끝이 벨트 면 아래로 → 손목 관절 오차로 실패.
- **해결:** B에서 −2 mm를 빼고 C 한 곳에만 둠. 자동 분류에서 작은 볼트·큰 볼트 상자 성공 확인. C도 이후 벨트 멈춤 경로에 같은 보정을 추가.
- **배운 점:** 같은 보정이 두 파트에 있으면 경로에 따라 겹친다. 보정은 한 곳에만.

### 2.7 비스듬한 작은 볼트를 B가 "판정 불가"로 버림 (11-24, PR #172)
- 작은 볼트를 0~150°로 돌려 놓고 B 결과를 비교하는 스크립트로 시험.

| 각도 | B 판정 | 각도 오차 | 잰 길이 (실제 22 mm) |
|---|---|---|---|
| 0° | BOLT_A | −2.1° | 19.3 mm |
| 30° | BOLT_A | −5.4° | 18.4 mm |
| 45° | BOLT_A | −1.0° | 17.8 mm |
| 150° | 판정 불가 → **수정 후 BOLT_A** | −1.4° | 16.4 mm |

- **원인:** 비스듬할수록 끝점 길이가 짧게 잡혀 하한 17 mm 아래로 떨어짐.
- **해결:** 작은 볼트 길이 하한 **17 → 14 mm** (큰 볼트 하한 36 mm라 사이 여유 충분).

### 2.8 실행 환경 문제들
| 문제 | 원인 | 해결 |
|---|---|---|
| 시간이 뒤로 가고 카메라 FPS가 2배 | 새벽에 켠 Gazebo가 안 꺼지고 남아 두 개가 겹침 | `ps`로 찾아 종료 → 이후 A가 실행 시 남은 Gazebo 자동 정리(`run_mode`) 추가 |
| `--ros-link requires rclpy` | `export PYTHONPATH=src`가 ROS 경로를 덮어씀 | `PYTHONPATH=src:$PYTHONPATH` |
| `No module named 'moveit_configs_utils'` | 기본값이 MoveIt 켜짐인데 미설치 | `start_moveit:=false` → 이후 MoveIt 설치 |
| 창마다 ROS 도메인이 30/42로 다름 | 수업용 설정이 `.bashrc`에 30을 씀 | 한 PC 안의 모든 창을 42로 통일 |
| 터미널 붙여넣기 중 한글·긴 줄 깨짐 | 터미널 줄바꿈 | 수정은 패치 파일·스크립트 파일로 전달 |

## 3. 원인은 찾았지만 아직 반영 안 한 것

### 3.1 자동 분류에서 B가 명령을 버림 (`B_TIMEOUT`)
- **현상:** 두 개 잡고 나서 볼트가 계속 지나가기만 함. 로그 기록상 B가 `B_TIMEOUT`으로 86번 버림.
- **원인:** B는 사진 한 장 계산이 20 ms를 넘으면 목표를 버림. 평소 1~2 ms인데, Gazebo·YOLO·추적·MoveIt·대시보드가 한 PC에서 돌면 넘어감.
- **시험:** 100 ms로 늘리니 **86번 → 1번**, 뒤 볼트도 계속 잡으러 감. 명령마다 2초 유효시간이 따로 있어 안전.
- **남은 일:** A의 시험 파일이 20 ms를 고정 확인하고 있어, A 확인 후 함께 변경 예정.

## 5. 정리

- B가 맡은 좌표 계산은 Gazebo 정답 대비 **위치 1~1.5 mm, 각도 1~5°, 속도 ±0.6 mm/s** 안으로 검증했다.
- 통합에서 실패할 때마다 **로그로 실패 이유를 확인 → 조건 하나만 바꿔 비교 시험 → B 문제면 고치고, 아니면 근거와 함께 해당 파트에 전달**하는 순서로 진행했다.
- 남은 문제는 인식(각도), 추적(가림), 그리퍼(물리) 쪽이며, 원인 후보와 재현 방법을 팀에 공유했다.
